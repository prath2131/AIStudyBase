# StudyBase

This is a persistent study companion. Upload PDF chapters, articles, or syllabi once, then the user can ask questions about them anytime and get a direct, cited answer instead of re-reading the whole document.

**The problem:** Revisiting material you've already studied to find a specific concept costs 10–20 minutes of re-reading or re-searching, every time.

**The 10x claim:** Re-finding a concept in a PDF you've already saved drops from 10–20 minutes of re-reading to under 30 seconds — via a direct question, answered with a citation back to the source page.

---

## Concepts implemented (5, 1 swap)

| # | Concept | Where it lives in the code |
|---|---------|------------------------------|
| 1 | API endpoints | `main.py` — `/documents/`, `/ask/`, `/reports`, `/auth/login` |
| 2 | Database | Postgres + SQLModel — `models.py` (`Document`, `Page`) |
| 3 | Authentication | Supabase Auth (login/signup) + FastAPI dependency `get_current_user` that verifies the Supabase JWT and scopes all data by `owner_id` |
| 4 | RAG with citations *(swap for LLM integration)* | `/ask/` in `main.py` — Postgres full-text search (`tsvector`/GIN index) over saved pages, answer generated by a local LLM (Ollama, `gemma3:1b`), grounded in retrieved excerpts, returned with page-level citations |
| 5 | Reporting | `/reports` in `main.py` + `pdf_generate.py` — queries the user's saved documents and renders a PDF summary using `fpdf2` |

**Swap reason:** RAG with citations was used instead of plain LLM integration because the core value of this project is answers grounded in the user's own saved material with a page-level source reference — not a generic chatbot call.

---

## Stack

- **Language/framework:** Python 3.10+, FastAPI
- **Database:** Postgres (Docker), SQLModel
- **Auth:** Supabase Auth, JWT verification in FastAPI
- **PDF extraction:** `pypdf`
- **Search:** Postgres full-text search (`tsvector` + GIN index, `websearch_to_tsquery` with OR-based term matching)
- **LLM:** Ollama, `gemma3:1b`, OpenAI-compatible API — local, free, no API key required
- **Reporting:** `fpdf2`
- **Config:** `.env` + `python-dotenv`

## Setup

### Prerequisites
- Python 3.10+
- Docker Desktop (or Podman)
- [Ollama](https://ollama.com) installed, with the model pulled:
  ```
  ollama pull gemma3:1b
  ```
- A free [Supabase](https://supabase.com) project (for auth) — grab your project URL and anon/public key

### Steps

1. **Clone the repo and enter the project folder**
   ```
   git clone <your-repo-url>
   cd studybase
   ```

2. **Create a virtual environment and install dependencies**
   ```
   python -m venv .venv
   .venv\Scripts\activate      # Windows
   pip install -r requirements.txt
   ```

3. **Set up your `.env` file** (copy `.env.example` if provided, or create `.env`):
   ```
   DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/studybase
   SUPABASE_URL=<your-supabase-project-url>
   SUPABASE_ANON_KEY=<your-supabase-anon-key>
   SUPABASE_JWT_SECRET=<your-supabase-jwt-secret>
   ```

4. **Start Postgres**
   ```
   docker compose up -d
   ```

5. **Start Ollama** (if not already running as a background service)
   ```
   ollama serve
   ```

6. **Run the app**
   ```
   uvicorn main:app
   ```
   The API is now available at `http://127.0.0.1:8000`, with interactive docs at `http://127.0.0.1:8000/docs`.

## 5-minute demo path

1. **Sign up / log in** via `POST /auth/login` (using a Supabase test account) to get a JWT.
2. **Upload a sample PDF** via `POST /documents/` (use `Authorization: Bearer <token>`) — try one of the sample PDFs in `/samples`.
3. **Ask a question** via `POST /ask/`, e.g.:
   ```json
   { "question": "What is the projected market size for the smart home market?" }
   ```
   You'll get back a grounded answer plus citations pointing to the exact document and page it came from.
4. **List your library** via `GET /documents/` to see everything you've saved.
5. **Generate a report** via `GET /reports` — downloads a PDF summary of your saved documents.

## What I noticed while building this (concept 3 checkpoint)

- The RAG pipeline works correctly end-to-end: a question about market size returned a correct, cited answer from the right page.
- When asked something with no answer in the material (e.g. "who is the CEO"), the model correctly said the material didn't contain a clear answer, instead of guessing — the "what to do when unsure" instruction in the prompt held up.
- Full-text search with a raw question (`websearch_to_tsquery` on the full sentence) was too strict — it required every significant word to match on the same page (implicit AND), which caused real, relevant pages to be missed. Switching to an OR-based query (matching on any significant word, ranked by `ts_rank`) fixed this.
- Even with OR-based ranking, common/generic query terms (e.g. "data", "methods") sometimes failed to surface the most relevant page in the top 3 results, while including a rare/unique term from the same page dramatically improved retrieval. This suggests the ranking could be improved further — e.g. weighting phrase matches higher or retrieving more candidate pages — noted here as a possible future improvement rather than something fixed in this build.
- `gemma3:1b` is a small model; on at least one occasion it failed to extract a clearly-present answer from a correctly-retrieved excerpt. A larger local model would likely perform more reliably, at the cost of speed/resource usage.

## Non-goals

- No video, webpage/URL, or scanned/image PDF input — text-based PDFs only.
- No UI investment beyond a plain functional API — the focus was backend depth (extraction, RAG, persistence), not frontend polish.

## Future ideas

- Video/transcript input support
- Webpage/URL scraping input support
- OCR support for scanned/image PDFs
- A background/cron job to proactively resurface saved-but-unrevisited material
- Include Q&A history in the generated report, not just the document list
- Improve search ranking (phrase weighting, larger candidate pool)
